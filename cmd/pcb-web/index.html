PCB Layout Generator

Configure component clusters, power-source rows, and trace routing
Canvas and appearance
Component clusters
Inner scale must be smaller than middle scale. Set either radius bound to randomize every cluster component; an unset bound falls back to the cluster base radius. Leaving both bounds at zero preserves the existing cluster sizing behavior. Power contacts use the separately configured power-source component radius. Component count excludes power-source contacts. Power feeds are randomized between the configured minimum and maximum; 0 allows a cluster to have no power connection.
Power-source rows
Every configured contact is rendered. Active contacts are distributed among clusters according to the minimum and maximum feed counts. Unused contacts remain visible. The total configured contacts must satisfy the minimum feed count.
Placement constraints
The trapezoid uses the outermost contacts on the top and bottom rows and requires both rows. It constrains components and all routes.
Grid and traces
Complete randomized passes over all power feeds for each component placement.
Complete board-generation attempts. After placement/routing exhaustion, the generator retries with a seed derived from the current seed.
The generator attempts a small randomized set of links between clusters. It is normal for no inter-cluster traces to appear when no non-crossing route is available.
Best-effort count of base-color trace bundles from cluster leaf components. Each finds the nearest power, inter-cluster, or earlier decorative route within two grid steps, then runs parallel to it at a one-cell offset. Decorative traces are added last. Each bundle may use multiple parallel lines. If no suitable nearby route exists, no decoration is added. Set the count to zero to disable.
Best-effort base-color traces from power-source contacts not assigned to any active feed. They use the same nearby-route and parallel-offset behavior, and are skipped when no suitable route is available.
This is an upper bound. Power feeds automatically use fewer tracks when the source or destination core is too small; larger viable cluster components are preferred as destinations.
